# 0.3 - Initialisation du dépôt Git

## Phase

Phase 0 — Amorçage du projet

## Statut

Terminée

## Objectif

Placer le projet sous contrôle de version avant la première ligne de code, avec un `.gitignore` adapté à Godot 4 (pour ne jamais versionner le cache `.godot/` ni les exports) et un `README.md` racine présentant le projet.

Cette story ne produit **aucun commit** : le premier commit interviendra à la fin de la phase 0, une fois la gate franchie.

## Dépendances

- `0.2 - Backlog, squelette QA et suivi d'avancement`

## Critères d'acceptation

1. `git init` a été exécuté à la racine du dépôt ; `git status` répond sans erreur.
2. La branche par défaut est nommée explicitement (`main`), et ce choix est consigné en Notes.
3. `.gitignore` existe à la racine et ignore au minimum : `.godot/`, `.import/`, `export.cfg`, `export_presets.cfg`, `build/`, `*.translation`, `.DS_Store`, `*.tmp`.
4. `git status --porcelain` ne fait apparaître **aucun** fichier issu d'un dossier ignoré.
5. `README.md` existe à la racine et contient : titre du jeu, pitch en 2-3 lignes, stack (Godot 4.x / GDScript), version de Godot requise, arborescence du dépôt, et un renvoi vers `cahier_des_charges_motherload_40k_godot.md`, `stories/BACKLOG.md` et `qa/README.md`.
6. `README.md` mentionne le prérequis « Godot 4.x doit être installé pour lancer et tester le jeu ».
7. Aucun commit n'a été créé par cette story (`git log` vide), et aucun remote n'a été ajouté.
8. Aucun fichier de code de production n'est créé.

## Référence cahier des charges

- « Vision » — titre, genre, moteur, plateforme (contenu du README).
- « Pitch » — résumé à reprendre dans le README.
- « Architecture Godot » — arborescence à décrire dans le README.

## Notes / décisions

- **Action critique** : `git init` doit être **annoncé avant exécution** conformément à `.claude/CLAUDE.md`.
- Le `.gitignore` doit être posé **avant** la création du projet Godot (story `1.1`), sinon le dossier de cache `.godot/` généré au premier import serait suivi par erreur.
- Pas de `git add` global à l'aveugle : vérifier `git status` après création du `.gitignore`.
- Le push et l'ajout d'un remote restent à l'initiative de l'utilisateur.

### Décisions prises pendant l'exécution (2026-08-29)

- **`git init` autorisé explicitement par l'utilisateur** avant exécution. Git 2.50.1 (Apple Git-155).
- **Branche par défaut : `main`**, fixée explicitement par `git init -b main` plutôt que par une
  configuration globale `init.defaultBranch`. Motif : le choix reste porté par le dépôt lui-même et
  ne dépend pas de la configuration de la machine ; `main` est la convention des plateformes
  d'hébergement (GitHub, GitLab) et évite un renommage ultérieur.
- **Aucune configuration Git locale ajoutée** (ni `user.name`, ni `user.email`, ni hooks, ni
  `core.autocrlf`) : hors périmètre de la story, à trancher par l'utilisateur avant le premier commit.
- **`.gitignore`, choix structurants** :
  - `.godot/` couvre tout le cache d'import de Godot 4 (`uid_cache.bin`, `imported/`, `editor/`).
  - `.import/` (avec barre oblique finale) ne vise que l'**ancien dossier** de cache Godot 3. Les
    fichiers `<asset>.import` posés **à côté** des assets ne sont volontairement **pas** ignorés :
    en Godot 4 ils portent l'UID de la ressource et doivent être versionnés, sans quoi les `.tscn`
    casseraient sur une autre machine. Un commentaire dans le fichier le rappelle.
  - `export_presets.cfg` est ignoré (chemins locaux et éventuels secrets de signature).
  - Ajouts au-delà du minimum exigé : artefacts d'export (`*.pck`, `*.zip`, `*.exe`, `*.x86_64`,
    `*.wasm`, `*.apk`…), temporaires (`*.bak`, `*.swp`, `*.log`, `*~`), OS (`._*`, `Thumbs.db`),
    IDE (`.vscode/`, `.idea/`) et résidus Mono/C#.
- **Vérification du `.gitignore` par test réel** : des fichiers factices ont été créés dans
  `.godot/`, `.godot/imported/`, `.import/`, `build/`, plus `export.cfg`, `export_presets.cfg`,
  `.DS_Store`, `fr.translation` et `scratch.tmp`. `git status --porcelain` est resté inchangé
  (6 entrées `??` seulement : `.claude/`, `.gitignore`, `README.md`, le CDC, `qa/`, `stories/`) et
  `git check-ignore -v` a confirmé la règle appliquée pour chacun. Les fichiers de test ont ensuite
  été supprimés ; la racine est revenue à son état initial.
- **README** : le prérequis moteur annonce « Godot 4.x doit être installé pour lancer et tester le
  jeu » et précise la version réellement utilisée, **4.7.2 stable** (`godot --version` →
  `4.7.2.stable.official.ed1daf0bf`, binaire `/opt/homebrew/bin/godot`), conformément à la story `0.6`.
- **README, deux arborescences distinctes** : l'état réel du dépôt (documentation seule) et
  l'arborescence cible `res://` de la section « Architecture Godot » du CDC, explicitement datée
  des stories `1.1`/`1.2`. L'autoload `GameData.gd` y figure au titre de l'arbitrage Q4.
- **Périmètre tenu** : aucun commit (`git rev-list --all --count` → 0), aucun remote
  (`git remote -v` vide), aucun `git add` (index vide), aucun fichier de code de production
  (`find` sur `*.gd`, `*.tscn`, `*.tres`, `project.godot` → aucun résultat).
- **Constat de vérification (hors périmètre, à signaler)** : `git status --porcelain --ignored` fait
  apparaître une seule entrée ignorée, `.claude/settings.local.json`. La règle ne vient **pas** du
  `.gitignore` du projet mais du fichier d'exclusion global de la machine
  (`/Users/jeremie/.config/git/ignore:1: **/.claude/settings.local.json`). Comportement souhaitable
  (réglages locaux d'outil), mais **non portable** : sur une autre machine, ce fichier serait proposé
  au suivi. Décision d'ajout éventuel au `.gitignore` du dépôt laissée au `po`.
- **Reste à l'initiative de l'utilisateur** : identité Git (`user.name` / `user.email`), ajout d'un
  remote, et le premier commit `Phase 0 — Amorçage du projet` après la gate `0.4` → `0.5`.
