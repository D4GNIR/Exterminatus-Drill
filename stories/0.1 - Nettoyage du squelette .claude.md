# 0.1 - Nettoyage du squelette .claude

## Phase

Phase 0 — Amorçage du projet

## Statut

Terminée

## Objectif

Aligner le squelette méthodologique `.claude/` sur la réalité du projet : un jeu **Godot 4 / GDScript**, et non le projet **Next.js** décrit par le template d'origine. À l'issue de cette story, la documentation et les agents doivent décrire le bon stack, référencer les bons fichiers, et ne plus pointer vers des ressources inexistantes.

## Dépendances

Aucune (première story du projet).

## Critères d'acceptation

1. `.claude/README.md` ne mentionne plus Next.js / App Router / TypeScript / Tailwind, et décrit le stack Godot 4 + GDScript.
2. Un agent développeur existe réellement dans `.claude/agents/` et correspond au stack Godot ; plus aucune référence à un agent `fullstack-nextjs` inexistant.
3. `.claude/agents/product-owner.md` référence `.claude/CLAUDE.md` (et non `.claude/clude.md`).
4. Toute référence au cahier des charges pointe vers le fichier réellement présent à la racine : `cahier_des_charges_motherload_40k_godot.md`.
5. Le dossier `stories/` existe et contient cette story.
6. Aucun fichier de code de production n'est créé par cette story.

## Référence cahier des charges

- « Vision » — Moteur : Godot 4.x, GDScript ; plateforme PC + export Web.
- « Architecture Godot » — arborescence `res://` de référence pour l'agent dev.

## Notes / décisions

- **Origine du problème** : le squelette `.claude/` provient d'un template de projet Next.js réutilisé tel quel. Trois incohérences relevées à l'audit initial : README au mauvais stack, agent `fullstack-nextjs` référencé mais absent du disque, chemin `.claude/clude.md` fautif dans l'agent PO.
- **Nom du cahier des charges** : le template attend `cahier-des-charges.md`. Décision de **conserver le nom existant** `cahier_des_charges_motherload_40k_godot.md` (plus explicite, et déjà rempli) et de corriger les documents qui le référencent — plutôt que de renommer un fichier déjà écrit. Point de vigilance : sans cette correction, l'agent PO aurait créé un second CDC vide en doublon.
- **Numérotation** : phase 0 réservée à l'amorçage méthodologique (squelette, outillage, dépôt), afin que la phase 1 reste dédiée aux fondations du jeu lui-même.
- **Hors périmètre de cette story** : création du squelette `qa/`, du `BACKLOG.md` et du `git init`. Le `qa/` et le backlog relèvent du PO ; le `git init` fera l'objet d'une story dédiée.
- **Nom de l'agent dev** : `godot-dev` (et non `fullstack-nextjs`). Toutes les références documentaires ont été alignées sur ce nom.
- **Godot absent de la machine** : ni dans le `PATH` (`godot`, `godot4`), ni dans `/Applications`. Les agents ne peuvent donc ni lancer le jeu ni exécuter `godot --headless --check-only`. Cette limite est désormais documentée dans `.claude/agents/godot-dev.md` et dans `.claude/README.md` : la validation d'exécution incombe à l'humain lors de la story de tests manuels. **Action requise côté utilisateur : installer Godot 4.x.**
- **Vérification finale** : `grep -rniE 'next\.?js|tailwind|app router|typescript|clude\.md|cahier-des-charges'` ne remonte plus que cette story elle-même (trace historique volontaire). Les 6 critères d'acceptation sont satisfaits.
