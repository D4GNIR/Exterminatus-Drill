# 1.1 - Initialisation du projet Godot 4

## Phase

Phase 1 — Fondations techniques du projet Godot

## Statut

À faire

## Objectif

Créer le projet Godot 4.x lui-même : un `project.godot` valide et minimal, écrit **à la main** (l'éditeur Godot n'étant pas disponible sur cette machine), configuré pour un jeu 2D en vue latérale, avec un nom de projet, une résolution de référence et un renderer explicites.

C'est la fondation de toutes les stories suivantes : sans `project.godot` valide, rien ne peut être importé.

## Dépendances

- `0.3 - Initialisation du dépôt Git` (le `.gitignore` doit exister avant qu'un import Godot ne génère `.godot/`).

## Critères d'acceptation

1. `project.godot` existe à la racine du dépôt et contient `config_version=5` (format Godot 4.x).
2. La section `[application]` définit :
   - `config/name="Exterminatus Drill"` (titre provisoire du CDC),
   - `config/features` déclarant la version Godot 4.x visée et `"Forward Plus"` ou `"GL Compatibility"` selon le renderer retenu.
3. La section `[display]` définit une résolution de fenêtre de référence et un mode d'étirement (`window/stretch/mode`, `window/stretch/aspect`) explicitement choisis et justifiés en Notes.
4. Le renderer est explicitement déclaré dans `[rendering]` ; le choix est justifié en Notes au regard de la cible « PC + export Web possible » du CDC.
5. `run/main_scene` est soit absent, soit pointé vers une scène **réellement existante** — il est renseigné définitivement en story `1.6`. Aucune référence à un fichier inexistant.
6. Le fichier ne contient **aucune** clé propre à Godot 3 et aucun bloc généré incohérent (`load_steps`, UID inventés).
7. `icon.svg` (ou équivalent) référencé par `config/icon` existe, ou la clé est absente — pas de référence morte.
8. **[H]** Le projet s'importe dans Godot 4.x sans erreur (`TM-1.1`) et se lance avec `F5` sans erreur console (`TM-1.2`).
9. Aucun script `.gd` ni scène `.tscn` n'est créé par cette story.

## Référence cahier des charges

- « Vision » — Godot 4.x / GDScript, 2D latérale en tuiles, PC avec export Web possible.
- « Architecture Godot » — le projet doit accueillir l'arborescence `res://` contractuelle.

## Notes / décisions

- `project.godot` est rédigé à la main au format INI de Godot 4, puis **validé immédiatement** par `godot --headless --quit` depuis la racine : toute clé mal formée ou section inconnue ressort dans la sortie. Cette validation est exigible en audit `1.7`. Seuls restent `[H]` les critères de rendu (résolution effective, fenêtre).
- **Action critique** : toute modification de `project.godot` doit être annoncée avant exécution (`.claude/CLAUDE.md`).
**Arbitrage utilisateur — tranché le 2026-08-29.** **Q1 — Renderer : `GL Compatibility`.** Motif : le CDC vise « PC, avec export Web possible » ; `Forward Plus` fermerait cette cible. Le coût est nul pour de la 2D en tuiles (sprites, particules de poussière, étincelles). Conséquence assumée : pas de lumières 2D ni de glow natifs — l'ambiance grimdark passera par les assets et la palette, pas par le rendu.
  - À écrire dans `project.godot` : `rendering/renderer/rendering_method="gl_compatibility"` **et** `rendering/renderer/rendering_method.mobile="gl_compatibility"` (les deux clés, sinon l'export mobile/web repasse au défaut).
- **Résolution de référence — décidée par défaut, non arbitrée par l'utilisateur** : base **1280×720** (16:9), `display/window/stretch/mode="canvas_items"`, `aspect="expand"`. Choix révisable en phase 3 une fois la taille de tuile fixée : à 32 px/tuile cela donne 40×22,5 tuiles visibles, ce qui est un cadrage lisible pour du forage vertical. **À reconfirmer avant la story 3.2.**
