# 1.7 - Audit qualité — Sprint 1

## Phase

Phase 1 — Fondations techniques du projet Godot

## Statut

À faire

## Objectif

Première story de **gate** du sprint 1. Auditer statiquement tout ce qu'a produit la phase 1 (projet Godot, arborescence, Input Map, `GameState`, données JSON, scènes squelettes) à l'aide de `qa/audit-qualite-reference.md`, et rendre un verdict **Autorisé** ou **KO**.

C'est le premier audit de code du projet : il pose le niveau d'exigence pour toute la suite.

## Dépendances

- `1.1` à `1.6` toutes au statut **Terminée**.

## Critères d'acceptation

1. La checklist `qa/audit-qualite-reference.md` est parcourue **point par point** ; chaque point reçoit OK / KO / N/A.
2. Les sections applicables au sprint 1 sont couvertes en priorité : **A** (arborescence), **B** (GDScript), **C** (couplage), **D** (données JSON), **F** (Input Map), **I** (cohérence documentaire), **J** (dépôt et configuration).
3. Les sections **E** (TileSet), **G** (règles de gameplay) et **H** (robustesse d'état runtime) sont marquées **N/A** avec justification, sauf pour les points déjà applicables (bornage des jauges de `GameState` : H1, H2).
4. Chaque KO est documenté avec sa **preuve** : code du point, description, `fichier:ligne`, et sévérité (bloquant / mineur).
5. Vérifications spécifiques effectuées et tracées :
   - typage statique sur 100 % des variables et fonctions de `GameState.gd` et du chargeur de données ;
   - `grep` confirmant l'absence de `get_node("..`, `$"../`, `get_parent().get_parent()` dans `scripts/` ;
   - `grep` confirmant l'absence de `KEY_` / test de touche en dur dans `scripts/` ;
   - les 12 actions de l'Input Map présentes dans `project.godot` ;
   - validation syntaxique des 3 fichiers `data/*.json` par un parseur ;
   - `run/main_scene` pointant vers un fichier existant ;
   - toutes les `ExtResource` des `.tscn` pointant vers des fichiers existants.
6. Aucun critère d'acceptation marqué `[H]` dans les stories `1.1` à `1.6` n'a été coché par un agent : ils sont tous reportés à la story `1.8`.
7. Chaque fichier créé pendant la phase 1 est rattaché à une story ; aucun fichier orphelin.
8. Le **verdict** daté, avec décompte OK/KO/N-A et liste des KO, est consigné en *Notes / décisions* au format imposé par `qa/audit-qualite-reference.md`.
9. En cas de **KO** : une story de correction est créée dans la phase 1 (numérotée à la suite, sans renumérotation des existantes) ; la story `1.8` **n'est pas démarrée** tant que le verdict n'est pas **Autorisé**.

## Référence cahier des charges

- « Architecture Godot » — conformité de l'arborescence et des arbres de scènes.
- « Contrôles » — complétude de l'Input Map.
- « Ressources » / « Améliorations » — cohérence des données JSON avec les tableaux du CDC.
- « Données de tuile » — cohérence anticipée des `resource_id`.

## Notes / décisions

- **Audit statique + headless** : relecture de code pour les conventions (typage, couplage, arborescence), et **preuve d'exécution** pour la syntaxe et le chargement — `godot --headless --check-only` sur chaque `.gd`, `godot --headless --quit` sur le projet. Joindre la sortie en preuve. Rappel : une sortie contenant `ERROR:` est un échec même avec exit code 0.
- Un audit trop indulgent au sprint 1 se paie aux sprints suivants : les points bloquants (typage, couplage, données externalisées, Input Map) sont ici peu coûteux à corriger, et très coûteux plus tard.
